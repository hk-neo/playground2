## 1. 소개

### 1.1 목적

본 문서는 로컬 CBCT 웹 뷰어 소프트웨어의 개발 계획(SW Development Plan)을 정의한다.
IEC 62304:2006+A1:2015 Section 5.1 요구사항에 따라 소프트웨어 개발 라이프사이클 전반의 활동과 책임을 명시한다.
### 1.2 범위

본 계획은 다음 활동에 적용된다:
- 요구사항 분석
- 소프트웨어 아키텍처 설계
- 소프트웨어 상세 설계 (Class A 면제)
- 구현 및 코딩
- 검증(Verification) 및 확인(Validation)
- 형상 관리
- 위험 관리

대상 소프트웨어는 로컬 CBCT 웹 뷰어 v1.0이며, 의료기기 소프트웨어(SaMD)로서 II급 일반의료기기, IEC 62304 Software Safety Class A로 분류된다.

Software Safety Class A에 해당하므로 다음 활동이 적용된다:

| IEC 62304 Section | 활동 | Class A 적용 |
|-------------------|------|-------------|
| 5.1 | SW 개발 계획 | 필수 |
| 5.2 | SW 요구사항 분석 | 필수 |
| 5.3 | SW 아키텍처 설계 | 필수 |
| 5.4 | SW 상세 설계 | 면제 |
| 5.5 | 단위 구현 및 검증 | 면제 |
| 5.6 | SW 통합 및 통합 테스트 | 필수 |
| 5.7 | SW 시스템 테스트 | 필수 |
| 5.8 | SW 출시 | 필수 |

개발 방법론은 V-Model을 기반으로 하며, 각 설계 단계는 대응되는 테스트 단계와 추적성을 유지한다:

## 4. 요구사항 관리

### 4.1 요구사항 수집 및 분석

요구사항은 다음 소스로부터 수집 및 분석된다:

| 요구사항 소스 | 내용 | Jira 키 |
|-------------|------|---------|
| Intended Use | 제품의 의도된 사용 목적, 사용자, 환경 | PLAYG-1962 |
| Classification | 의료기기 분류, Software Safety Class | PLAYG-1964 |
| System Requirement | 시스템 기능/비기능 요구사항 | PLAYG-1970~1982 |

요구사항 분석 절차:
1. IU 및 Classification 문서에서 제품 컨텍스트 파악
2. 시스템 요구사항을 기능/비기능으로 분류
3. 각 요구사항의 우선순위 및 구현 복잡도 평가
4. 요구사항 간 의존성 분석
5. 이해관계자 검토 및 승인

## 5. 설계 및 구현

### 5.1 아키텍처 설계

소프트웨어 아키텍처 설계는 다음 원칙에 따라 수행한다:

- 모듈 분리: 영상 처리 로직과 UI 렌더링 로직을 분리
- 인터페이스 명확화: 모듈 간 인터페이스를 명확히 정의하여 결합도 최소화
- 성능 고려: 512x512x512 볼륨 데이터 실시간 렌더링을 위한 아키텍처 설계
- 보안 By Design: SR-012 요구사항을 아키텍처 수준에서 반영

주요 아키텍처 구성 요소:

| 컴포넌트 | 역할 | 관련 요구사항 |
|---------|------|-------------|
| DICOM Parser | DICOM 파일 파싱 및 데이터 추출 | SR-001 |
| Volume Manager | 볼륨 데이터 관리 및 메모리 최적화 | SR-001, SR-010 |
| MPR Renderer | Axial, Coronal, Sagittal 단면 렌더링 | SR-002 |
| 3D Renderer | Ray Casting 기반 3D 볼륨 렌더링 | SR-003 |
| Camera Controller | 회전, 확대, 축소 카메라 제어 | SR-004 |
| Window Controller | WL/WW 조절 기능 | SR-005 |
| Measurement Tool | 거리/각도 측정 도구 | SR-006 |
| ROI Tool | 관심영역 표시 기능 | SR-007 |
| Patient Info | 환자 정보 표시 | SR-008 |
| Sync Manager | MPR-3D 뷰 동기화 | SR-009 |
| UI Layer | 웹 브라우저 UI | SR-011 |
| Security Module | 로컬 데이터 처리, 외부 전송 차단 | SR-012 |
### 5.2 상세 설계

Class A에 해당하므로 IEC 62304 Section 5.4 상세 설계는 면제이다.
단, 다음 사항은 아키텍처 설계 단계에서 정의한다:
- 모듈 간 인터페이스 정의
- 주요 데이터 구조 정의
- 알고리즘 개요 설계

### 5.3 코딩 표준

| 항목 | 기준 |
|------|------|
| 프로그래밍 언어 | TypeScript, JavaScript |
| UI 프레임워크 | React 또는 Vue.js |
| 렌더링 엔진 | Three.js / WebGL 2.0 |
| 코딩 컨벤션 | ESLint + Prettier |
| 명명 규칙 | camelCase - 변수/함수, PascalCase - 클래스/컴포넌트 |
| 주석 규칙 | JSDoc 형식으로 공개 API 주석 작성 |
| 버전 관리 | Git, 의미있는 커밋 메시지 |

## 6. 검증 및 검수

### 6.1 단위 테스트

IEC 62304에 따라 Class A는 단위 테스트가 면제이나, 품질 향상을 위해 권장한다:

| 항목 | 내용 |
|------|------|
| 테스트 프레임워크 | Jest 또는 Vitest |
| 커버리지 도구 | Istanbul/c8 |
| 목표 커버리지 | 핵심 모듈 80% 이상 - 권장 |
### 6.2 통합 테스트

IEC 62304 Section 5.6에 따라 소프트웨어 통합 테스트를 필수로 수행한다.

| 항목 | 내용 |
|------|------|
| 목적 | 모듈 간 인터페이스 검증 및 통합 동작 확인 |
| 대상 | 전체 모듈 통합 후 소프트웨어 시스템 |
| 방법 | 기능별 통합 테스트 케이스 작성 및 수행 |
| 판정 기준 | 모든 통합 테스트 케이스 통과 |
| 산출물 | 통합 테스트 보고서 |

주요 통합 테스트 항목:

| 테스트 항목 | 관련 요구사항 | 설명 |

| DICOM 파싱 - MPR 렌더링 | SR-001, SR-002 | 파일 로드 후 MPR 생성 검증 |
| DICOM 파싱 - 3D 렌더링 | SR-001, SR-003 | 파일 로드 후 3D 렌더링 검증 |

| 성능 기준 달성 | SR-010 | 렌더링 성능 측정 검증 |
| 보안 요구사항 | SR-012 | 외부 전송 차단 검증 |

### 6.3 시스템 테스트

IEC 62304 Section 5.7에 따라 소프트웨어 시스템 테스트를 필수로 수행한다.

| 항목 | 내용 |

| 방법 | 요구사항 기반 시스템 테스트 케이스 작성 및 수행 |
| 환경 | Chrome, Edge 최신 버전, Windows 10/11, macOS |
| 판정 기준 | 모든 시스템 테스트 케이스 통과 |
| 산출물 | 시스템 테스트 보고서 |
